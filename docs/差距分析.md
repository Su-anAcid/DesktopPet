# 与同类桌宠的对比 · 差距分析

> 对照对象：Shimeji-ee、BongoCat（24.3k★）、VPet 虚拟桌宠模拟器、Desktop Mate（Steam）、oneko-swift / Neco
> 结论先行：**这个项目的"骨架"（动画密度、体积、原生实现）在开源同类里是第一梯队，但"产品化外壳"（安装、更新、找回、扩展）明显落后，这是它现在最大的短板。**

---

## 一、横向定位

| 项目 | 形态 | 体积 / 运行时 | 核心卖点 | 生态 |
|---|---|---|---|---|
| **本项目 DesktopPet** | 2D 程序化像素 | **0.86MB** / 原生 Swift・Win32 | 76 帧动作 + 完整过渡时间轴 | ❌ 无 |
| Shimeji-ee | 2D 精灵 | ~27MB + JRE | 爬墙、抓起抛掷、分裂 | ✅ 角色包海量 |
| BongoCat | Live2D | 数十 MB / Tauri | 键鼠联动、打鼓 | ✅ 模型库 |
| VPet 虚拟桌宠模拟器 | 2D WPF | 百 MB 级 / .NET | 养成数值 + 学习计时 | ✅ Steam mod |
| Desktop Mate | 3D Unity | GB 级 / Steam | 官方角色 DLC | ✅ 商业 DLC |
| oneko / Neco | 2D 极简 | KB 级 | 猫追鼠标 | ❌ 无 |

## 二、我们的真实优势（别在改进中丢掉）

1. **体积与依赖**：0.86MB、零运行时。BongoCat 装完是几十 MB 量级，Shimeji 得先装 Java——这是小红书用户最在意的一层门槛。
2. **动画密度**：76 帧 + 状态机 + 过渡时间轴（舔爪 2~3 遍、扫尾、起身张望）。绝大多数开源 2D 桌宠只有「走 / 站 / 坐」三套循环。
3. **数据即代码**：像素画是程序化画出来的，换毛色只改调色板。做新角色不需要美术资源。
4. **双平台同源**：macOS 与 Windows 共用同一套精灵数据，改一次两边都有。

## 三、不足（按影响排序）

### 🔴 P0 — 直接卡住传播（小红书用户装不上 / 用不下去）

**1. 没有 Apple 公证，首次打开提示「已损坏」**
- 现状：ad-hoc 签名，Gatekeeper 直接拦。
- 对比：BongoCat 走 Homebrew + 签名分发；Desktop Mate 走 Steam，安装环节不过 Gatekeeper。
- 影响：**这是最大的漏斗。** 小红书来的用户 80% 卡在这一步，还得我一条条回复「右键→打开」。
- 改法：Apple Developer $99/年 公证（notarytool + stapler）；短期至少补 Homebrew cask + 图文安装指引。

**2. 没有自动更新**
- 对比：Sparkle 是 macOS 桌面小工具的标配；Steam 版天然自动更新。
- 影响：我修了 bug，1.0.0 的用户永远停在 1.0.0，收不到修复。发布节奏再快也没用。
- 改法：Sparkle 2 + appcast.xml（CI 里自动生成），约半天工作量。

**3. 猫丢了就找不回来 —— 没有菜单栏图标**
- 现状：`NSStatusItem` 完全没有，唯一入口是右键那只猫。
- 对比：oneko-swift、Neco 都常驻菜单栏。
- 影响：猫被拖到屏幕角落、或外接屏拔掉后位置错乱，用户以为程序崩了，只能强退。
- 改法：`NSStatusItem` + 显示/隐藏、回到右下角、快捷开关。

**4. 所有设置塞在右键菜单里**
- 现状：毛色/大小/节奏/固定/舔爪/开机自启/关于，已经 9 项。
- 影响：再加功能菜单就崩了；也没法做首次启动引导。
- 改法：独立偏好窗口（哪怕是 SwiftUI 的 Preferences Scene），右键菜单只留高频项。

### 🟠 P1 — 体验差距（同类有、我们没有）

**5. 不理鼠标、不理键盘**
- 对比：BongoCat 跟着敲键盘打鼓、oneko 追鼠标转圈，这是它们的核心快感来源。
- 现状：只有"点一下"才响应，猫像在自顾自走。
- 改法：低频轮询鼠标位置（10Hz 足够），猫头转向 / 靠近时抬头看 / 快速划过时受惊——成本很低，亲密度提升最大。

**6. 不能抓起来扔**
- 对比：Shimeji 的招牌就是拖拽抛掷 + 撞墙反弹。
- 现状：只能拖动放下，松手就站住。
- 改法：拖拽速度 → 抛物线 + 落地压缩帧 + 受惊表情。

**7. 没有任何声音**
- 喵一声、呼噜、踩奶，是最便宜的"活物感"。同类里 Desktop Mate 有语音，我们完全静音。

**8. 只有一只猫，不能换角色 → UGC 为 0**
- 对比：Shimeji 角色包、BongoCat 模型库、VPet mod，生态是它们的护城河。
- 现状：用户只能换毛色，不能加新形象，也做不了二次创作。
- 影响：内容天花板低，社区起不来，Star 增长缺"自来水"。
- 改法：定义 `pet.json`（精灵图 + 行为参数 + 调色板），支持丢一个文件夹就换宠物。

**9. 不与系统状态联动**
- 空白地带：深夜犯困、电量低趴下、勿扰模式睡觉、专注计时陪跑。
- 成本很低但故事性极强，是"这只猫懂你"的关键。

### 🟡 P2 — 工程与细节

**10. 30fps 常驻重绘**：睡觉时也 30fps 跑 `updateImage()`，笔记本用户能感知到耗电。改为状态驱动帧率（idle 8fps / sleep 1fps / walk 30fps）+ 帧未变不重绘。
**11. 全屏应用不隐藏**：`collectionBehavior` 带 `fullScreenAuxiliary`，看视频、放 PPT 时猫会盖在画面上，办公室场景很尴尬。需要检测全屏 App 自动隐藏。
**12. 只支持中文**：README、菜单、About 全中文，GitHub 英文社区看不懂 → 少了一大半潜在 Star。
**13. Windows 版功能不对齐**：有托盘菜单和单实例，但没有设置持久化、没有开机自启、托盘图标也缺，双平台体验不一致。
**14. 无自动化测试**：`PREVIEW` 只打印帧尺寸校验；没有像素快照对比，改动画容易悄悄画歪。`SpriteData.swift` 1002 行单文件，`App.swift` 711 行，该拆了。
**15. 缺社区基建**：无 CONTRIBUTING、无宠物格式文档、无 issue 模板，别人想贡献无处下手。

## 四、不建议抄的（会伤害定位）

- **VPet 的饥饿/打工数值**：会把"安静陪伴"变成每日打卡负担，和工位场景冲突。
- **Shimeji 的满屏分裂**：办公室会被同事投诉，且违背"不打扰"。
- **3D / Live2D**：体积暴涨百倍，还会毁掉像素风的差异化。

---

## 五、建议路线（按投入产出比）

| 周期 | 做什么 | 为什么先做这个 |
|---|---|---|
| **这周** | 菜单栏图标 + 状态驱动帧率 + 全屏自动隐藏 | 全是低风险小改动，直接提升"像成品"的感觉 |
| **这周** | Sparkle 自动更新 | 发布之后还能修 bug |
| **两周内** | 追鼠标 + 抓起来扔 | 交互深度的天花板，视频也更好看 |
| **一月内** | 英文 README + Homebrew cask + Apple 公证 | 决定 GitHub 能不能被外国人 star |
| **长期** | `pet.json` 自定义宠物格式 | 唯一的生态护城河，让别人帮你做内容 |

> 一句话：现在的差距不在"猫画得好不好"，而在"产品有没有把用户当第一次用电脑的人来对待"。
